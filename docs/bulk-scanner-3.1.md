# BMD Scan 3.1 — experimental bulk scanner

Adds the ZXing-C++ Android 2.3.0 multi-symbol decoder (pinned dependency) for QR and Data Matrix, retaining the proven Java narrow-bar decoder for linear barcodes. 2D mode includes QR and Data Matrix; combined mode adds linear barcodes. Dense images use overlapping native passes instead of relying on one pass's 255-symbol ceiling. Full-resolution capture decoding is performed off the UI thread.

LotData extracts supported GS1 fields from HRI or separator-delimited data: GTIN (01), lot (10), expiry (17); unrecognised fields/data do not become guessed lots. Unknown/conflicting lots remain marked for review. Manual lot edits are identified in exported rows. Lot colours appear only in numbered check badges and legend dots, never in product outlines. Colour assignments persist and do not indicate shipment approval.

ProductCatalog deliberately does not equate matching code content with physical identity. Symbols start as separate provisional product records. The operator groups codes belonging to the same physical box in Review products; split reverses grouping. Different decoded lots, GTINs or expiry dates cannot be merged. A grouping review is required before save/share/export. Grouped export rows retain every source payload and extracted lot metadata. Live camera motion and occlusion can still cause tracking ambiguity; manual review is necessary. This release does not perform automatic package-boundary detection.

Captured image marks are restricted to code IDs actually observed in that captured image; the full session still retains prior product records. Original code payloads and group assignments remain saved separately. Reopening a session requires review again.

Validation includes JVM parsing/grouping/200-record tests and Android native-decoder tests for 13 mixed-lot symbols, 200 equal-payload Data Matrix symbols, explicit merge/split UI, and cropped real owner examples. Crops exclude unrelated surroundings. These test fixtures are not production shipment labels. Photo decoding uses overlapping small regions and a nearest-neighbour enlarged pass for small source images. Counts decoded from real crops are logged; synthetic 200-symbol success is NOT validation of 200 real products, nor proof of 100% safety. Real Galaxy S26 / dense cartons / hidden labels and shipment reconciliation require further validation. The APK remains a test build and must not replace an approved distribution final check.
